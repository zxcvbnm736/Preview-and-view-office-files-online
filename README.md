# -execl-word-
一个基于 Manifest V3 的浏览器扩展，让你在网页上点开一个附件就能立刻看到内容，还能改几个单元格、抓出图片里的文字，然后直接存回本地。Word 预览与导出、Excel/CSV 预览编辑、图片查看、本地 OCR、右键菜单、附件下载接管
## 功能特性

### Word 预览与编辑

- 打开 `.docx`，保留标题层级、段落、表格、图片、列表和文字颜色
- 轻量编辑后可以导出为 `.docx`

### Excel 预览与编辑

- 打开 `.xlsx`、`.csv`、`.tsv`
- 单元格的值和样式都能改，支持另存为 `.xlsx` 或 `.csv`
- 尽量保留原有的表格格式与颜色
- 支持多张工作表

### 图片查看与编辑

- 打开图片直接查看，并可另存一份副本

### OCR 文字提取

- 从图片里提取文字，支持中文和英文
- 提取结果可复制，也可导出
- OCR 由扩展内置的本地引擎完成，**不联网**

### 右键快捷入口

在任意网页的链接或图片上右键，即可：

| 菜单项               | 作用                      |
| ----------------- | ----------------------- |
| 用 Office 预览器打开此文件 | 把链接指向的 Office 文件直接送进预览器 |
| 用 Office 预览器查看此图片 | 在预览器里打开图片               |
| 提取此图片中的文字 (OCR)   | 对图片跑一次本地 OCR            |
| 打开 Office 预览器     | 直接打开一个空白的预览器标签页         |

工具栏图标单击同样可以打开预览器。

### 附件下载接管（可关闭）

很多后台系统（OA、网盘、企企这类）的附件接口带 `Content-Disposition: attachment`，浏览器只会默默下载。

扩展默认开启「下载接管」：当一次下载被判定为 Office 文件时，取消这次落盘，改为把同一个 URL 交给预览器渲染 —— 附件直接变成预览页，硬盘上不留垃圾文件。

如果你更希望正常下载，可以关闭这个开关（对应 `chrome.storage.local` 里的 `interceptDownloads`，默认 `true`）。

## 隐私

- **文件不上传。** 所有解析和渲染都在你的浏览器本地完成，没有任何服务器参与。
- **不收集数据。** 没有统计、没有埋点、没有账号体系。
- **离线可用。** 解析库和 OCR 模型全部打包在扩展内，断网也能工作。
- **只读你主动打开的文件。** 扩展申请了宽泛的主机权限，是因为用户要打开的文件可能来自任何网址；但它只会读取你明确点开的那个文件。
### 商店安装

已提交至 Microsoft Edge 加载项商店，审核通过后可直接搜索安装。

## 使用

**方式一：工具栏**
点工具栏图标 → 预览器在新标签页打开 → 用界面里的打开按钮选本地文件。

**方式二：右键**
在网页里的链接或图片上右键，选择合适的菜单项。

**方式三：下载即预览**
保持「下载接管」开启，正常去点后台系统的附件下载，文件会自动在预览器里打开。

## 技术实现

纯原生前端，仓库内不含 `package.json` / `node_modules` / 构建产物，24 个文件即全部源码，改完刷新扩展就生效。

| 文件                      | 职责                                             |
| ----------------------- | ---------------------------------------------- |
| `manifest.json`         | MV3 清单：权限、Service Worker、右键菜单入口                |
| `background.js`         | 后台 Service Worker：右键菜单、打开预览器标签页、接管 Office 附件下载 |
| `viewer/viewer.html`    | 预览器主界面，类 WPS 的工具栏布局                            |
| `viewer/app.js`         | 界面主控与交互编排                                      |
| `viewer/word.js`        | Word 文档渲染                                      |
| `viewer/docx-writer.js` | 导出 `.docx`                                     |
| `viewer/sheet.js`       | 表格渲染与单元格编辑                                     |
| `viewer/xlsx-style.js`  | 表格样式（字体 / 填充 / 边框 / 合并 / 列宽）处理                 |
| `viewer/xlsx-write.js`  | 导出 `.xlsx`                                     |
| `viewer/image.js`       | 图片查看与 OCR 调用                                   |
| `viewer/common.js`      | 通用工具函数                                         |
| `viewer/style.css`      | 界面样式                                           |
| `libs/`                 | 第三方解析库（见下）                                     |
| `lang/`                 | Tesseract 中文 / 英文识别模型                          |

### 依赖（均已打包进扩展）

- [JSZip](https://stuk.github.io/jszip/) — 解压 / 打包 OOXML 容器
- [mammoth.js](https://github.com/mwilliamson/mammoth.js) — `.docx` 转 HTML
- [SheetJS (xlsx)](https://sheetjs.com/) — `.xlsx` / `.csv` 读写
- [Tesseract.js](https://github.com/naptha/tesseract.js) — 本地 OCR 引擎（WASM + 中文 / 英文模型）

为满足 MV3 的内容安全策略，`manifest.json` 里声明了 `'wasm-unsafe-eval'`，用于加载 OCR 的 WASM 内核。

## 已知限制

- 复杂排版（分栏、文本框、艺术字、域代码、脚注）无法完全还原
- 超大 `.xlsx` 和 OCR 首次识别需要几秒，属正常现象
- Word 导出的排版与原文件可能存在细微差异，建议导出前确认关键版式
- 目前商店信息仅提供英文（美国），其他语言界面后续补充
